# apps/mobile: GameVerse Unity project

Unity **6000.6.8f1** (Unity 6.6; moves to 6.7 LTS when released, see [ADR-0004](../../docs/architecture/adr-0004-unity-editor-version.md)), URP with the 2D Renderer, UI Toolkit. Android first (IL2CPP, ARM64, min API 26, id `app.gameverse.mobile`).

## Commands (repo root)

```
make rules         # build GameVerse.Rules + Contracts, copy DLLs and golden fixtures into this project
make unity-setup   # apply project settings and generated assets (ProjectSetup.Apply), idempotent
make unity-test    # EditMode tests headless -> apps/mobile/TestResults/editmode.xml
make android       # development IL2CPP APK -> apps/mobile/Build/Android/GameVerse.apk
make device-check  # install on the USB phone, launch, check GV_SELFCHECK (rules) and GV_ERRORCHECK (error reporting)
```

`unity-setup` and `android` run through `infrastructure/scripts/unity-batch.mjs`. Unity 6000.6.8f1 on Windows can hang on shutdown ("Killing ADB server") after the work is done. The wrapper waits for our completion marker (`GV_SETUP` / `GV_BUILD`) in the log, gives the editor 60 s to exit, then ends the process tree. It sets the exit code from the marker.

On another machine, point `UNITY=` (and `ADB=`) at your editor. Linux / CI (GameCI image `unityci/editor:ubuntu-6000.6.8f1-android-3`, licence via `UNITY_LICENSE` or serial):

```
unity-editor -batchmode -nographics -projectPath apps/mobile \
  -runTests -testPlatform EditMode -testResults TestResults/editmode.xml -logFile -
```
(`-runTests` quits by itself; do not add `-quit`. Exit code 0 = all passed, 2 = test failures, 1 = editor/compile error.)

## Layout

```
Assets/GameVerse/
  Core/        GameVerse.Core      IGameModule, IGameHost (CLAUDE.md 4.2), GameStateEnvelope
  Net/         GameVerse.Net       GameVerseJson: Newtonsoft settings matching the server's System.Text.Json
  UI/          GameVerse.UI        Tokens.uss + Tokens.g.cs (generated), Theme/, Components/ (GameCard, ButtonStyle), Home/, Fonts/
  Platform/    GameVerse.Platform  Boot (scene entry), Diagnostics/RulesSelfCheck
  Games/Ludo/  GameVerse.Games.Ludo  one assembly per game (empty until Prompt 1.6)
  Plugins/Shared/  GameVerse.Rules.dll + GameVerse.Contracts.dll (build output of `make rules`, never edit) + link.xml
  Resources/Fixtures/  golden JSON copied by `make rules` (gitignored)
  Editor/      ProjectSetup (all settings as code), BuildScript
  Tests/EditMode/  PRNG parity, wire format round trip
  Scenes/Boot.unity, Rendering/ (URP asset: renderer 0 = 2D, renderer 1 = Forward+ for 3D games)
```

An `.asmdef` makes a folder its own compiled assembly with explicit references, roughly a Maven module. Assemblies that use the shared DLLs list them in `precompiledReferences`. Game rules are never reimplemented here: games call `GameVerse.Rules`.

## Rules for this project

- Settings and generated assets come from `Editor/ProjectSetup.cs`. Change them there, not by clicking, so diffs stay reviewable.
- UI uses only `var(--gv-*)` from `Tokens.uss` and `GameVerseTokens` from `Tokens.g.cs` (both generated by `make tokens`).
- Every REST/realtime payload goes through `GameVerseJson.Settings`, never Newtonsoft defaults (which rename dictionary keys).
- Development builds log one `GV_SELFCHECK` line at boot: the shared PRNG vectors run under IL2CPP must match `dotnet test`.
- Error reporting (ADR-0005): the Sentry Unity SDK (4.11.0) reports to GlitchTip. `ProjectSetup` writes `Assets/Resources/Sentry/SentryOptions.asset`:
  - PII, screenshots, view hierarchy and in-editor capture are off;
  - IL2CPP line numbers and Android native crash and ANR capture are on;
  - the `GameVerseSentryConfiguration` hook sets the environment and strips the user block.

  The committed asset never holds a DSN. `make android` reads `UNITY_ERROR_DSN` from `.env`, and `BuildScript` puts it into the asset only for the duration of the build. Development builds log `GV_ERRORCHECK sent|disabled` and send one info event. Unity's own analytics, crash and performance reporting are switched off.
